# THPT PDF and image extraction worker

The standalone `pdf-worker` service consumes pending extraction jobs created by the backend. It downloads PDFs or images from the active S3-compatible object store (MinIO locally, or R2 when selected in environment configuration). PDFs use embedded text or OCRmyPDF/Tesseract. PNG, JPEG, and WebP images are validated, rotated using EXIF orientation, normalized to PNG, and read locally with Tesseract (`vie+eng`). The resulting OCR text and the allowed subject catalog are sent to the effective `EXTRACTION` model through the OpenAI-compatible `/chat/completions` text API. The worker validates the model's JSON against the public `subjects` catalog and writes review drafts; it never publishes to `subject_groups` or stores raw OCR text. Each image is source page 1.

## PostgreSQL contract

The backend Flyway migration V6 places workflow tables in the `admin` schema. V7 adds the `CANCELLED` extraction-job state used during final document deletion. V8 renames `admin.extraction_jobs` to `admin.extraction_log` and adds the graph-sync outbox. V10 adds soft-delete fields to schools, subject groups, and drafts. The worker reads and writes `admin.extraction_log`, `admin.school_document_versions`, `admin.school_documents`, and `admin.subject_group_drafts`. The subject catalog remains in `public.subjects`.

Apply backend migrations through V10 before starting the updated worker services. Use the same target PostgreSQL database in backend and worker configuration. The connection account must have access to both `admin` workflow tables and `public` school/group tables.

The worker does not claim jobs for documents in `DELETE_REQUESTED` or `DELETED`. It locks the document before claiming and before writing extraction results, then rechecks that the job is still `RUNNING`. A job already running when a legacy delete request is recorded may finish and save drafts while leaving the document in `DELETE_REQUESTED`. When ADMIN or SUPER_ADMIN soft-deletes the document, the backend changes pending/running/retry jobs to `CANCELLED`; any late worker result is discarded. Failure/retry handling also preserves a legacy delete-requested state.

## Configuration

Set `OBJECT_STORAGE_PROVIDER` (`MINIO` or `R2`), `OBJECT_STORAGE_ENDPOINT`, `OBJECT_STORAGE_BUCKET`, `OBJECT_STORAGE_REGION`, `OBJECT_STORAGE_ACCESS_KEY_ID`, and `OBJECT_STORAGE_SECRET_ACCESS_KEY`, plus `DATABASE_URL` (or backend datasource fallback) and `LLM_API_KEY`, `LLM_API_BASE`, and `LLM_MODEL` in local environment files. Do not commit actual credentials. Backend and worker must select the same provider, bucket, endpoint and credentials. Use `OBJECT_STORAGE_INTERNAL_ENDPOINT` for the Docker network endpoint when it differs from the host endpoint; the backend uses `OBJECT_STORAGE_PUBLIC_ENDPOINT` to sign browser-download URLs. The worker image installs OCRmyPDF, Pillow, and Tesseract with Vietnamese and English language data. Image uploads are limited to 10 MiB and 20 megapixels; PDFs retain their 50 MiB limit. Image OCR has a 60-second default timeout, configurable with `IMAGE_OCR_TIMEOUT_SECONDS`.

The worker is included in the monorepo's root `docker-compose.yml` as `pdf-worker`, with MinIO and its idempotent bucket-initialization job. Start the complete stack from the monorepo root with `docker compose up -d --build`. MinIO API is available on `http://localhost:9000` and its console on `http://localhost:9001`; the MinIO volume persists objects across container restarts. When running the worker directly on Windows, use `OBJECT_STORAGE_ENDPOINT=http://localhost:9000` and `LLM_API_BASE=http://localhost:20128/v1`. Docker Compose sets the worker's endpoint to the internal service address and `LLM_API_BASE` to `http://host.docker.internal:20128/v1`. `localhost` inside a container refers to that container, not Windows. The worker retries failed jobs up to `PDF_WORKER_MAX_ATTEMPTS`; a missing object is terminal and reported as `STORAGE_OBJECT_MISSING`.

When switching provider, update the `OBJECT_STORAGE_*` values for both backend and worker and restart them. The current provider reads only from its selected bucket; old objects are not copied between R2 and MinIO. While MinIO is active, old R2-only files cannot be downloaded or reprocessed. The backend returns HTTP 404 for a document whose key is absent from the active store. The MinIO Compose image builds pinned official source tag `RELEASE.2025-10-15T17-29-55Z`; upstream's release guidance recommends source builds for containers, and the upstream repository was archived in April 2026, so review the distribution before upgrading the pinned version.

The extraction model receives text for both PDFs and images, so it does not need vision support. The system prompt tells it to extract only the “Tổ hợp môn lựa chọn” or “Nhóm môn lựa chọn” column, ignore “Chuyên đề học tập” and unrelated columns, map names to the allowed subject catalog, and omit groups with unclear or missing subjects. Each extracted group may contain one to four distinct subjects; the worker validates this before writing drafts. OCR failures are reported as `OCR_EMPTY`, `OCR_ENGINE_ERROR`, or `OCR_TIMEOUT`; an empty OCR result is not sent to the model. After changing the worker, rebuild and recreate the `pdf-worker` service, then retry a failed job from the admin document screen. Raw OCR text remains temporary and is not persisted.

## Published subject-group projection

`graph_projection_worker.py` claims the subject-group outbox and `admin.high_school_graph_sync_jobs` using `FOR UPDATE SKIP LOCKED`. It reads active schools/groups and per-group publication state from PostgreSQL. A shared PostgreSQL advisory lock serializes document jobs, school jobs and full sync; each writer reads current source state after acquiring the lock. Published groups are MERGEd. When a group's effective state becomes unpublished, the writer removes only its UID-scoped `SubjectGroup` node and attached relationships; shared `HighSchool` and `Subject` nodes remain. Document soft-delete alone still leaves the graph unchanged. Restore validates retained MinIO objects in the backend, republishes the PostgreSQL source, then queues projection that recreates the missing group node and relationships using the stable UID. Failed jobs use capped exponential backoff; only `GRAPH_SYNC_FAILED` is stored in the outbox. Document and school jobs print `[graph-sync] claimed`, `[graph-sync] retry`, or `[graph-sync] synced` with job and entity identifiers to worker stdout, visible through the Compose service logs. Configure PostgreSQL and Neo4j connections in local environment files. The worker does not call the LLM or access object storage.
